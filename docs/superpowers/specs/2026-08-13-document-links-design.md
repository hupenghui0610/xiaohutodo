# 文档链接功能设计

## 背景与目标

当前应用已经提供“To-do List”和“文档链接”两个一级入口，但文档链接面板仍为空占位。本次实现一个随账号保存的个人文档链接库，让用户按一级目录整理常用文档信息，避免遗忘并便于从描述中选择、复制网址或其他文字。

本功能保持现有单页应用、Cloudflare Pages Functions、D1 数据库和账号会话体系不变。文档链接采用独立的数据表、接口和前端模块，不复用或扩展待办数据模型，也不改变现有待办业务逻辑。

## 功能范围

### 文档链接

一条文档链接包含：

- 标题：必填，去除首尾空格后为 1–20 个 Unicode 字符。
- 描述：必填，去除首尾空格后为 1–100 个 Unicode 字符，通常用于保存网址，也可保存普通文字。
- 所属目录：必填，只能选择当前账号拥有的目录。
- 创建时间与更新时间：由服务端维护，用于排序和审计。

描述在查看态始终作为不可点击的纯文本显示，不识别网址、不生成超链接。用户可以使用浏览器原生的拖选和复制能力复制全部或部分文字。

每条文档右侧提供删除操作。删除必须经过应用内二次确认弹窗，确认后才向服务端提交。

### 目录

目录只有一级，不支持子目录。目录名称必填，去除首尾空格后为 1–20 个 Unicode 字符。同一账号内目录名称不可重复，比较时忽略英文大小写。

每个账号首次使用文档链接功能时，系统按以下顺序创建三个普通目录：

1. 赠品管理
2. 产品文档
3. 销售政策

三个初始目录不具备特殊权限，可以改名，也可以在为空时删除。账号一旦完成首次初始化，即使后来删除全部目录，系统也不得重新补建初始目录。

只有不包含任何文档链接的目录可以删除。空目录删除也必须经过应用内二次确认。非空目录的删除操作不可执行，并明确提示“请先删除或移动目录内的文档链接”。允许删除最后一个目录。

首版不支持目录或文档拖拽排序。目录按创建时间正序排列，创建时间相同时以目录 ID 保证稳定顺序；文档在各目录内按创建时间倒序排列，创建时间相同时以文档 ID 保证稳定顺序。移动文档不会改变其创建时间。

## 页面布局

### 公共页面框架

- 保留顶部“To-do List”和“文档链接”一级 Tab。
- To-do List 激活时，顶部右侧显示现有周切换区域。
- 文档链接激活时，顶部右侧隐藏周切换区域并显示“目录管理”按钮。
- 页面左下角现有“无限期、周待办、日待办”静态图例永久移除，不再参与 Tab 显隐。
- 页面右下角账号、修改密码、管理账号和退出等现有功能保持位置与行为不变。
- 登录页和认证流程不变。

### 文档链接主体

文档链接主体按目录纵向排列。每个目录使用一张沿用当前深色视觉系统的面板卡片：

- 卡片头部左侧显示目录名称，右侧显示“添加”按钮。
- 卡片内容按行展示文档。查看态下，左侧为标题，中间为可选中复制的描述，右侧为删除按钮。
- 新建文档始终显示在所属目录的最上方。
- 空目录保留卡片，内容区显示轻量空状态。
- 当账号没有任何目录时，显示“暂无目录”的全局空状态，并保留右上角“目录管理”入口。

视觉样式复用现有页面的背景、圆角、边框、间距、蓝色主按钮、灰色次按钮和红色危险操作规范，不照搬草图中的浅色表格样式。

桌面宽度下，查看行使用标题、描述和操作三段式布局。窄屏下改为纵向排列，标题和描述占满可用宽度，操作按钮换行显示，避免描述被压缩或横向溢出。

## 文档新增与编辑

点击目录卡片中的“添加”后，在该目录内容区顶部插入一条空白原位编辑行，不打开独立弹窗。编辑行包含：

- 标题输入框。
- 描述输入框。
- 所属目录下拉框，默认选中发起添加操作的目录。
- 保存与取消按钮。
- 字段级错误和请求错误区域。

点击现有文档的标题后，该行原位进入相同的编辑状态，同时允许修改标题、描述和所属目录。点击描述本身不触发编辑，以保证文字选择和复制稳定可用。

同一时间只允许一条新增或编辑行存在。当前存在未保存编辑时，其他标题和“添加”按钮暂不进入新的编辑状态，并提示用户先保存或取消当前编辑，避免静默丢失输入。

保存规则如下：

- 前端在请求前校验必填、长度和目录选择。
- 保存期间禁用当前行的保存、取消和目录切换，防止重复提交或状态竞争。
- 新增成功后转为查看态并位于目录顶部。
- 编辑成功后转为查看态；若更换目录，该记录立即从原目录移至目标目录，并按原创建时间参与目标目录排序。
- 保存失败时保留全部输入并显示行内错误，不刷新或清空编辑行。
- 取消新增会移除未保存的空白行；取消编辑会恢复进入编辑前的服务端数据。

输入区域显示当前字符数，并在接近或超过限制时使用现有提示色反馈。字符长度按 Unicode 码点计算，使中文和常见表情按一个字符计数；前后端使用同一规则。

## 目录管理弹窗

右上角“目录管理”打开与现有账号弹窗视觉一致的模态框。弹窗包括：

- 顶部新增目录输入框和“添加”按钮。
- 按创建顺序排列的目录列表。
- 每行显示目录名称、文档数量、改名和删除操作。
- 关闭按钮和必要的错误提示区域。

改名在当前目录行内完成，提供保存与取消。新增和改名均在前端先校验必填、长度及当前已知的重名，再由后端执行最终校验。

空目录的删除按钮可用，点击后打开应用内二次确认弹窗。非空目录的删除按钮禁用，并通过可见提示或辅助说明告知限制原因。删除最后一个目录后，主体进入无目录空状态；用户仍可再次打开目录管理创建目录。

弹窗支持关闭按钮、取消按钮和 `Esc` 关闭。关闭弹窗时仅放弃弹窗内未保存的新增或改名输入，不影响已经成功保存的数据。目录新增、改名或删除成功后，弹窗列表与主体目录卡片同步更新；请求失败时保留当前输入并显示明确错误。

## 数据模型

### `document_directory_states`

用于记录账号是否已完成初始目录创建，避免用户删除全部目录后系统再次补建。

- `user_id`：主键，外键关联 `users(id)`，账号删除时级联删除。
- `initialized_at`：完成初始化的服务端时间。

### `document_directories`

- `id`：目录主键，由服务端使用 `crypto.randomUUID()` 生成；客户端不能指定。
- `user_id`：所属账号，外键关联 `users(id)`，账号删除时级联删除。
- `name`：规范化后的目录名称。
- `name_key`：名称去除首尾空格并转为小写后的比较键，仅用于同账号重名约束。
- `created_at`：服务端创建时间。
- `updated_at`：服务端更新时间。

数据库为 `user_id` 和目录排序字段建立索引，并对 `(user_id, name_key)` 建立唯一约束。前后端使用 `trim()` 后的名称和 `toLocaleLowerCase('zh-CN')` 生成比较键；应用层先给出友好重名提示，数据库约束负责阻止并发请求创建重名目录。

### `document_links`

- `id`：文档主键，由服务端使用 `crypto.randomUUID()` 生成；客户端不能指定。
- `user_id`：所属账号，外键关联 `users(id)`，账号删除时级联删除。
- `directory_id`：所属目录，关联 `document_directories(id)`；删除目录使用限制策略，不级联删除文档。
- `title`：规范化后的标题。
- `description`：规范化后的描述。
- `created_at`：服务端创建时间。
- `updated_at`：服务端更新时间。

数据库为 `user_id`、`directory_id` 和文档排序字段建立索引。所有文档查询都同时限定 `user_id`，不能仅凭目录 ID 或文档 ID 访问数据。

## 初始目录创建

首次读取当前账号的目录时，后端在一个原子批次或事务等价流程中：

1. 检查 `document_directory_states` 是否已有该账号记录。
2. 若没有，则创建三个初始目录并写入初始化状态。
3. 若已有，则直接读取当前目录，即使目录数量为零也不补建。

初始化写入必须具备并发幂等性。状态表主键和目录唯一约束共同防止两个首次请求生成重复目录。任何一个初始化步骤失败时，不返回部分初始化成功的结果；下一次读取可以安全重试。

## API 设计

### `/api/document-directories`

- `GET`：确保首次目录初始化完成后，返回当前账号的目录列表及每个目录的文档数量，按创建时间正序排列。
- `POST`：创建目录。请求只包含名称；用户归属和服务端时间由后端确定。
- `PUT`：按目录 ID 修改名称。
- `DELETE`：按目录 ID 删除空目录。

删除目录时，服务端必须在执行删除的同一数据库操作或等价的原子保护中确认该账号该目录没有文档。不能只依赖前端显示的文档数量，否则并发新增可能造成误删。若目录非空，返回可识别的冲突错误；若目录不属于当前账号，对外统一表现为不存在。

### `/api/document-links`

- `GET`：返回当前账号的全部文档链接，按创建时间倒序排列；客户端再按 `directory_id` 分组。
- `POST`：创建文档，接收目标目录 ID、标题和描述。
- `PUT`：修改文档的标题、描述和目标目录，实现编辑与移动。
- `DELETE`：按文档 ID 删除文档。

创建或移动文档时，后端必须验证目标目录属于当前登录账号。所有更新和删除条件都同时包含资源 ID 与当前 `user_id`。请求体中的未知字段被忽略或拒绝，但绝不接受调用方提供的用户 ID、创建时间或更新时间。

### 通用接口规则

- 写操作沿用现有 `requireSameOrigin` 同源校验。
- 所有接口沿用现有 `requireUser` 登录校验和“必须先修改临时密码”限制。
- 成功和错误响应沿用项目现有 JSON 封装与错误码风格。
- 后端再次执行必填、长度、重名和所属关系校验，不信任前端状态。
- 账号被删除时，初始化状态、目录和文档通过外键级联删除。

## 前端模块与状态流

新增独立文档链接前端模块，负责：

- 首次加载目录和文档。
- 目录卡片及文档行渲染。
- 新增、原位编辑、移动和删除文档。
- 目录管理弹窗和确认弹窗。
- 加载、空状态、错误和重试状态。

一级 Tab 控制器仍只管理一级面板及关联顶部控件：

- To-do List：显示待办面板和周导航，隐藏文档面板与目录管理按钮。
- 文档链接：显示文档面板和目录管理按钮，隐藏待办面板与周导航。
- 移除对页脚左侧静态图例 `todoLegend` 的依赖，因为该图例将从标记中永久删除。

文档数据采用首次进入文档 Tab 时延迟加载。一次成功加载后保存在页面运行时状态中；新增、编辑、移动、删除或目录变化成功后，以接口响应更新状态，必要时重新读取以确保文档数量和排序与服务端一致。重新登录或认证状态重置时清空文档模块内存状态，防止同一浏览器会话中账号切换后短暂显示前一账号数据。

## 异常与安全处理

- 初次加载时显示加载状态；加载失败时显示错误和“重试”按钮。
- 普通新增或编辑失败显示在对应行内，并保留输入。
- 目录操作失败显示在目录管理弹窗内，并保留输入。
- 登录失效继续触发项目现有全局认证处理。
- 删除冲突、重名、目标目录失效等可预期错误使用明确中文提示。
- 页面通过 `textContent` 或表单 `value` 处理目录名称、标题和描述，不使用未经转义的 HTML 拼接用户内容。
- 描述区域不绑定点击编辑或跳转行为，避免干扰文字选择。
- 确认弹窗管理焦点，支持键盘操作；关闭后焦点返回触发按钮。
- 模态框打开时限制背景交互，`Esc` 行为与现有弹窗规范保持一致。

## 测试与验收

### 自动化测试

至少覆盖：

1. 新账号首次读取会依次获得“赠品管理、产品文档、销售政策”。
2. 初始目录只初始化一次；全部删除后再次读取仍为空。
3. 不同账号的目录和文档严格隔离。
4. 无法读取、修改、删除或引用其他账号的目录和文档。
5. 非空目录无法删除；空目录可以删除。
6. 目录名称的必填、1–20 字符、忽略大小写重名规则。
7. 标题 1–20 字符、描述 1–100 字符及 Unicode 码点计数规则。
8. 创建、编辑、移动和删除文档后数据、数量和排序正确。
9. 用户内容按纯文本渲染，不产生 HTML 注入或自动链接。
10. 新增和编辑取消不会写入或改变服务端数据。
11. 保存失败时前端保留输入，同一时间只能存在一条编辑行。
12. 文档 Tab 显示目录管理并隐藏周导航；待办 Tab 行为相反。
13. 左下静态图例从页面和 Tab 控制逻辑中移除，右下账号功能标记和行为不变。
14. Pages 构建包含新增前端模块和 API 文件，完整现有测试无回归。

### 人工验收

- 桌面视图中目录面板、文档行、按钮、弹窗与现有深色界面协调一致。
- 窄屏下文档行纵向排列，无内容裁切、横向溢出或按钮重叠。
- 用户可稳定拖选并复制描述中的部分文字，点击描述不会跳转或进入编辑。
- 点击标题可同时编辑标题、描述和所属目录。
- 添加操作在目标目录顶部生成空白编辑行；保存和取消行为符合设计。
- 删除文档与空目录均出现应用内二次确认；非空目录删除不可执行。
- 删除所有目录后仍能通过“目录管理”创建新目录，三个初始目录不会复现。
- Tab 来回切换无明显布局跳动，To-do List 的待办数据、周视图和右下账号功能保持正常。

## 非目标

- 不支持子目录。
- 不支持目录或文档拖拽排序、自定义排序或置顶。
- 不支持搜索、标签、收藏、归档或批量操作。
- 不支持描述中的可点击链接、链接预览、自动抓取网页标题或内容。
- 不支持富文本、Markdown、文件上传或附件。
- 不支持已删除数据恢复或回收站。
- 不重构现有待办业务、认证体系或账号管理功能。
