# 文档描述中的可点击链接设计

## 目标

文档链接界面的描述可以同时包含普通文字和多个网址。展示描述时，自动将其中所有完整的 `http://`、`https://` 地址渲染为可点击链接，并在浏览器的新标签页中打开。

## 范围

- 支持一段描述中的多个 HTTP(S) 链接。
- 保留原始文字、空格、换行和复制文本的能力。
- 链接后继续书写正文时，以空格、换行或常见中英文标点作为边界。
- 链接位于描述末尾时不要求额外分隔符。
- 不识别裸域名（例如 `www.example.com`）或 Markdown 链接语法。
- 不修改描述的保存格式、接口或数据库结构。
- 不改变标题点击编辑、删除及目录管理等既有交互。

## 识别规则

1. 从大小写不敏感的 `http://` 或 `https://` 起始位置扫描链接候选。
2. 空白字符、换行或常见中文正文标点 `，。；！？、` 结束当前候选；这些分隔字符仍按原样显示。
3. 从候选末尾移除不属于网址的英文句末标点，包括 `,.!?;:`。
4. 对 `)`、`]`、`}` 等闭合符号进行配对判断：候选中存在对应开符号时保留，否则从末尾移除。
5. 使用浏览器 `URL` 解析器验证候选；无效候选保持为普通文本。
6. 链接与后续中文正文之间没有任何分隔符时存在天然歧义，不承诺推断其边界。用户应添加空格、换行或标点。

示例：

- `需求：https://example.com/a?id=1，开发前阅读` 中，链接为 `https://example.com/a?id=1`。
- `参考 https://example.com/wiki/A_(B)。` 中，配对括号属于链接，句号不属于链接。
- `主地址：https://a.example 备用：https://b.example/docs#top` 中，两个地址分别可点击。

## 渲染与安全

- 不使用 `innerHTML` 处理用户输入。
- 将描述拆分为普通文本节点和 `<a>` 节点，脚本标签及其他 HTML 字符串仍只显示为文字。
- 链接使用原始、已验证的 HTTP(S) 地址作为 `href`。
- 链接设置 `target="_blank"` 与 `rel="noopener noreferrer"`。
- 链接样式应清楚表达可点击状态，并沿用现有颜色变量；键盘焦点保持可见。

## 代码边界

- 在 `document-links-ui.js` 中增加一个独立的描述分段/链接化单元，由文档行渲染函数调用。
- `document-links-state.js`、API 与数据库保持不变。
- 在 `index.html` 中仅补充描述链接的视觉样式。

## 测试与验收

自动化测试覆盖：

- 一段描述中的多个链接分别生成锚点。
- 普通文字及原有换行顺序保持不变。
- URL 查询串、片段和配对括号被保留。
- 链接末尾中英文标点不进入 `href`，但仍显示在原位置。
- 非 HTTP(S) 内容和无效 URL 不生成锚点。
- `<script>` 等输入保持纯文本，不创建可执行 DOM。
- 每个链接均包含安全的新标签页属性。
- 点击标题仍进入编辑，点击描述中的普通文字不触发编辑。

验收标准：用户在描述中输入多个、边界明确的 HTTP(S) 链接后，保存并返回展示状态，可以逐个点击并由浏览器打开对应地址；描述原文与其他文档操作不受影响。
