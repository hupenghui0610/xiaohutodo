# 文档目录顺序调整设计

## 目标

允许用户在“目录管理”弹窗中调整自己账号下一级目录的展示顺序。调整结果随账号保存，并同步用于目录管理列表、文档链接主页面和文档编辑时的所属目录选项。

## 用户交互

- 每个目录行在“改名”“删除”前增加“上移”和“下移”按钮。
- 点击“上移”或“下移”后，目录立即移动一位并自动保存，不增加单独的“保存顺序”步骤。
- 第一项的“上移”禁用，最后一项的“下移”禁用。
- 请求期间禁用该行的排序按钮，防止重复操作；失败时保留原顺序并在弹窗内显示错误。
- 不支持拖拽，不改变文档在目录内的排序。
- 按钮使用明确的 `aria-label`，键盘操作与鼠标点击行为一致。

## 数据与接口

- `document_directories` 增加非空整数 `sort_order`，顺序越小越靠前。
- 现有目录按原先的 `created_at, id` 顺序回填连续排序值，线上已有顺序不会突变。
- 初始三个目录依次写入 `0、1、2`；新增目录使用当前账号最大顺序值加一，始终追加到末尾。
- 目录列表统一按 `sort_order, created_at, id` 排列。
- 目录接口增加账号受限的相邻移动操作。服务端重新读取当前账号的有序目录，只允许 `up` 或 `down`，并原子交换目标目录与相邻目录的顺序值。
- 位于边界、目录不存在或目录不属于当前账号时返回明确错误；不能影响其他账号的数据。

## 客户端状态

- Store 暴露 `moveDirectory(id, direction)`。
- 请求成功后采用服务端返回的完整目录列表，保证主页面、弹窗和编辑下拉框顺序一致。
- 沿用现有账号 generation 防护，账号切换后丢弃旧账号仍在途的排序结果。

## 验证

- 数据库迁移验证现有目录顺序回填和新增目录末尾追加。
- API 测试覆盖上移、下移、边界、账号隔离和非法方向。
- Store 测试覆盖成功、失败、账号重置竞态。
- UI 测试覆盖按钮顺序、首尾禁用、点击调用和失败提示。
- 完整执行测试、语法检查、构建，并在桌面和窄屏下检查弹窗无溢出。
