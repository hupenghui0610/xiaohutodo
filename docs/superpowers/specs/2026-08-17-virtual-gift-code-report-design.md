# 虚拟赠品兑换码日报设计

## 目标

在现有 Cloudflare Worker `xiaohutodo-reminder` 中增加一条服务器端日报任务。每天北京时间 09:00，从指定飞书多维表格读取兑换码记录，统计每个课程的剩余可用卡号，并通过现有飞书机器人发送给已经绑定提醒的飞书账号。

本功能不创建或依赖 Codex 本地自动化任务。

## 数据源与统计口径

- 多维表格 App Token：`RZVbbE34jaTP2xsHh3Tcnv03n4d`
- 数据表 ID：`tbl2LVOGDfDhPqyL`
- 数据应用 App ID 作为 Worker 普通环境变量配置。
- 数据应用 App Secret 只保存为 Cloudflare Secret，不写入源码、配置文件或 Git。
- 通过多维表格记录搜索接口在服务端筛选：
  - `卡号` 不为空；
  - `申请人` 为空。
- 遍历全部分页结果，按 `课程名称` 分组计数。
- 不生成合计行。

## 定时执行

沿用现有 Worker 的 `0 1 * * *` Cron，即每天 UTC 01:00、北京时间 09:00。现有 09:00 待办提醒保持不变；赠品日报作为独立任务在同一次 scheduled 事件中运行。

两个任务互不依赖：任一任务失败时，另一任务仍可执行并单独记录错误。

## 接收人与机器人

- 发送应用 App ID：`cli_aab22f19f5395cc6`。
- 发送应用 App Secret 继续使用 Cloudflare Secret `FEISHU_APP_SECRET`。
- 接收人沿用 D1 表 `feishu_reminder_recipient` 中 `admin_hupenghui` 已启用的 `open_id`。
- 没有已启用接收人时跳过发送，并返回可诊断的跳过原因。

## 消息样式

消息使用飞书富文本 `post`，格式为：

1. 标题：`虚拟赠品兑换码数量`；
2. 第一行：`数据时间：YYYY年MM月DD日 HH:mm`，使用 Asia/Shanghai 时区；
3. 第二行：`——————`；
4. 每个课程一行：`课程名称：剩余XX个`；
5. 不显示合计。

课程按名称稳定排序，保证每日消息顺序一致。没有符合条件的记录时，仍发送消息并显示“暂无可用兑换码”。

## 组件边界

### 数据读取

新增独立函数负责获取数据应用令牌、调用记录搜索接口、处理分页和聚合课程计数。它只返回结构化统计结果，不负责消息发送。

### 消息生成

新增纯函数负责将数据时间和课程统计转换为飞书富文本消息 JSON，便于单元测试验证标题、正文行数据和无合计要求。

### 消息发送

复用现有机器人令牌和 `post` 消息发送逻辑。发送目标仍为绑定的 `open_id`。

### 调度与幂等

新增赠品日报执行函数。复用现有投递记录表，以独立槽位标识当天 09:00 的赠品日报，避免 Cron 重试导致重复发送；发送成功后保存飞书 `message_id`，失败时记录截断后的错误信息。

## 配置与密钥

Worker 新增以下配置：

- 普通变量：数据应用 App ID、多维表格 App Token、数据表 ID；
- Cloudflare Secret：数据应用 App Secret。

用户在聊天中提供过的两个 App Secret 均视为敏感信息，不出现在测试快照、日志、文档正文或提交记录中。部署时通过 Wrangler Secret 命令写入 Cloudflare。

## 错误处理

- 获取令牌、读取分页或发送消息失败时抛出包含飞书错误码和简短消息的错误，不记录令牌或 Secret。
- 飞书 429 和服务端错误使用有限次数重试；明确的权限或参数错误直接失败。
- 赠品日报失败时更新投递状态为 `failed`，便于日志排查和后续 Cron 重试。
- 分页统计必须以飞书返回的 `has_more` 和 `page_token` 为准，不假定固定记录总数。

## 测试与验收

自动测试覆盖：

1. 筛选请求包含“卡号非空、申请人为空”；
2. 多页结果能完整聚合，并正确处理课程名称字段的飞书文本结构；
3. 消息标题、数据时间和课程数量行正确；
4. 消息不包含合计行；
5. 无数据时显示空状态；
6. 09:00 运行赠品日报，12:30 和 17:00 不运行；
7. 赠品日报与原待办提醒互不阻断；
8. 同一天同一赠品日报槽位不会重复发送；
9. 现有提醒和飞书事件回调测试继续通过。

部署后进行一次只读数据统计验证和一次手动触发发送验证，确认实际飞书消息与设计一致，再保留每日服务器 Cron。
