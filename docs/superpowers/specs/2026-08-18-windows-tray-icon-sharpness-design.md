# Windows 托盘图标清晰度修复设计

## 背景

桌面应用使用包含 16、24、32、48、64、128 和 256 像素帧的 `build/app.ico`。窗口图标直接引用该 ICO，Windows 可以按显示缩放比例选择合适的帧；托盘图标目前先被 Electron 压缩成单一的 16×16 位图，再交给 Windows。在高 DPI 环境中，Windows 需要重新放大这张位图，因此托盘溢出面板中的图标比任务栏图标模糊。

## 方案

`createTray()` 继续读取现有 `build/app.ico`，但不再调用 `nativeImage.resize()`。创建 `Tray` 时直接传入保留全部尺寸表示的 `nativeImage`，由 Windows 根据当前 DPI 选择最匹配的图标帧。

本次不修改图标几何、颜色、ICO 生成器、窗口图标或安装包图标，也不增加显示缩放率监听逻辑。

## 错误处理

保持现有资源加载行为不变。该改动不引入新的运行时分支；若 ICO 缺失，仍沿用 Electron 当前的加载与报错行为。

## 测试与验收

- 在桌面品牌测试中断言 `Tray` 接收完整的 `nativeImage`，且托盘创建路径不调用 `resize()`。
- 先运行新增断言并确认它因现有 16×16 强制缩放而失败，再修改生产代码使其通过。
- 运行桌面品牌测试及完整项目测试，确认没有回归。
- Windows 高 DPI 环境中的最终视觉验收标准：托盘溢出面板中的图标不再因应用侧先压缩到 16×16 而被系统二次放大。
