# 文档编辑器紧凑布局设计

## 目标

优化文档新增和编辑区域的视觉密度，不改变字段、校验、保存、取消、目录移动或账号数据逻辑。

## 布局

- 桌面端使用两行结构：第一行左侧标题、右侧所属目录；第二行描述独占整行。
- 标题与目录列比例约为 `2fr / 1fr`，描述不再夹在两列之间。
- 描述框默认高度约两到三行，允许用户纵向拉伸。
- 字数提示继续紧邻对应字段并右对齐，字段错误仍显示在字段下方。
- 保存与取消紧贴编辑内容右下方；请求错误与操作区同处底部，不再依赖大块空白推到底部。
- 编辑器使用更轻的蓝色边框、较小内边距和一致的 8px 间距节奏。

## 响应式与可访问性

- 768px 以下标题、目录、描述全部单列排列，按钮保持可见且不产生横向滚动。
- 保留原生 label、键盘焦点、禁用态和错误区域。
- 添加与编辑使用完全相同的布局。

## 验证

- DOM 测试确认标题和目录位于顶部字段组，描述位于独占字段组，底部包含错误区和操作区。
- 静态样式测试确认桌面两列、描述跨列、移动端单列和紧凑间距规则。
- 在正式页面桌面宽度与 375px 下验证，无溢出、无控制台错误。
